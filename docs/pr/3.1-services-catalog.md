# feat(catalog): [FE-3.1] клиентский каталог услуг

## Задача и функционал

- ID: FE-3.1 (эпик 3. Каталог услуг, US-2)
- Доска: https://github.com/orgs/1378-TRPO/projects/4
- Что сделано:
    - экран `/services` для роли `client`
    - пункт «Услуги» в навигации
    - `GET /services` через `catalogService` и `useServices`
    - карточки: название, описание, цена (RUB), длительность
    - loading, error+retry, empty state
- Границы: фильтры/поиск, запись на услугу, менеджерский CRUD (FE-3.2)

## Подготовка проверки

- Ветка: `feature/3.1-services-catalog` от актуального `main`
- Backend: `GET /services` из BE-3.1

```powershell
npm install
npm run dev
```

## Экраны и сценарии для тестировщика

| №   | Предусловия           | Действие            | Ожидаемый результат                          |
| --- | --------------------- | ------------------- | -------------------------------------------- |
| 1   | Клиент вошел          | Открыть «Услуги»    | Каталог активных услуг                       |
| 2   | Пустой каталог на API | Открыть `/services` | Empty state                                  |
| 3   | Есть услуги           | Открыть `/services` | Имя, описание, цена, длительность видны      |
| 4   | API недоступен        | Открыть `/services` | Ошибка и «Повторить»                         |
| 5   | Механик/менеджер      | Открыть `/services` | Отказ по роли client                         |
| 6   | Узкая ширина          | Открыть каталог     | Карточки читаемы, длинный текст не ломает UI |

### Связанные API

| Метод | Путь        | Зачем         | Токен / роль    | Успех | Ошибки       |
| ----- | ----------- | ------------- | --------------- | ----- | ------------ |
| GET   | `/services` | Каталог услуг | Bearer `client` | `200` | `401`, `403` |
