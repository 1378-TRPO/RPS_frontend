# feat(auth): [1.2] вход по JWT и роли клиента, механика, менеджера

## Задача и функционал

- ID: 1.2
- Эпик: 1. Пользователи и доступ
- Оценка: 3 SP
- Что сделано на фронте:
    - вход `POST /auth/login`, сохранение JWT access token и срока
    - защищенные маршруты по валидному токену
    - `GET /auth/me` после входа: email и актуальная роль
    - отображение ролей `client` / `mechanic` / `manager` в шапке и на главной
    - выход чистит токен и кэш запросов
    - при `401` сессия сбрасывается, редирект на `/login`
- Границы: профиль клиента (1.3) не расширялся; ссылка на профиль только у `client`.
  Refresh-токенов и logout на API нет.

Ветка собрана от `main` с переносом `feature/1.1-registration`, чтобы не терять регистрацию,
пока 1.1 не влит.

## Подготовка проверки

- Ветка: `feature/1.2-jwt-auth`
- Node.js 22+, backend с JWT (`JWT_SECRET` и миграции)

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

- Frontend: `http://127.0.0.1:5173`
- Backend: `http://127.0.0.1:8000` / Swagger `/docs`

Тестовые аккаунты (пароли свои, не публиковать):

- клиент: регистрация через `/register` или `POST /auth/register`
- механик / менеджер: CLI на беке `python -m app.cli create-staff --email ... --role mechanic|manager`

## Экраны и сценарии для тестировщика

| №   | Предусловия                      | Действие            | Ожидаемый результат                                  |
| --- | -------------------------------- | ------------------- | ---------------------------------------------------- |
| 1   | Клиент зарегистрирован           | Вход на `/login`    | Редирект на `/`, роль «Клиент», email в шапке        |
| 2   | Механик создан CLI               | Вход тем же экраном | Роль «Механик», пункта «Профиль» нет                 |
| 3   | Менеджер создан CLI              | Вход                | Роль «Менеджер»                                      |
| 4   | Неверный пароль                  | Вход                | Ошибка, без входа                                    |
| 5   | Неизвестный email                | Вход                | Та же формулировка ошибки, что и при неверном пароле |
| 6   | Пользователь вошел               | Обновить страницу   | Сессия сохраняется, `/auth/me` отрабатывает          |
| 7   | Пользователь вошел               | Выйти               | Токен очищен, редирект на `/login`                   |
| 8   | Истекший / битый токен в storage | Открыть `/`         | Редирект на логин                                    |
| 9   | Узкая ширина                     | Войти               | Роль видна в навбаре, бургер работает                |

### Связанные API

| Метод | Путь          | Зачем                   | Токен / роль          | Успех | Ошибки       |
| ----- | ------------- | ----------------------- | --------------------- | ----- | ------------ |
| POST  | `/auth/login` | JWT                     | Нет; любая из 3 ролей | `200` | `401`, `422` |
| GET   | `/auth/me`    | Email и актуальная роль | Bearer; все 3 роли    | `200` | `401`        |
